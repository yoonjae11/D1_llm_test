How to repair
1. Read the diagnostic. Find the operator and the name it complains about.
2. Trace that name back through the pipeline: was it never a column of the
   source (check the function's columns), or was it dropped or renamed by an
   earlier project/summarize/join?
3. Change as little as possible to fix every visible instance of the problem.
   Keep the question's meaning: the same source relation, measurement,
   activity filter, conditions, thresholds, selection, period bounds, sleep
   night label and final reduction. Never switch to another measurement or
   activity just to make the query compile.
4. Keep the result columns Metric, Aggregation, Value, Unit, EvidenceRows and
   ResultStatus, with Value = real(null) when there are no observations.

Common diagnostics and their fixes
- "Failed to resolve scalar expression named 'X'" after summarize: summarize
  only keeps its by-columns and aliases. Compute X in that summarize, or keep it
  in the by-clause, then refer to the alias.
    wrong: | summarize Total = sum(DurationMin) | project Value = Total, EvidenceRows = count()
    right: | summarize Total = sum(DurationMin), EvidenceRows = count() | project Value = Total, EvidenceRows
- "Failed to resolve ... 'sum_X'" or "'count_'": an unnamed aggregate gets a
  generated name; give every aggregate an explicit alias (Total = sum(X)).
- An alias used in the same extend/project where it is defined: split it into
  two operators (| extend A = ... | extend B = A * 2).
- "Function 'count' cannot be invoked in current context": aggregates only run
  inside summarize; toscalar(count()) is not valid. Use summarize ... count().
- count(*) is SQL; KQL uses count(). iff needs three arguments.
  row_count() does not exist.
- "@then data type (long) must match the @else data type (real)" or "case:
  return types are not compatible": the branches of iff, case and coalesce
  need one type; convert with todouble(), e.g. iff(n > 0, todouble(n), real(null)).
- "Cannot compare values of types timespan and long": a duration compares
  with a timespan (> 0s, >= 30m); divide it by 1m for a number of minutes.
- "Failed to resolve ... 'IngestionTime'" on SensorSleepNights or an activity
  rollup: those are already deduplicated; drop the arg_max(IngestionTime, ...)
  step there.
- "Unknown function": use standard KQL (avg, sum, min, max, stdev, stdevp,
  dcount, countif, sumif, percentile, make_list, take_any, row_number,
  array_sort_asc, array_length). sort_array does not exist: use
  array_sort_asc. Keep an exact calculation exact: a median stays the average
  of the middle one or two sorted values, not percentile().
- A let variable with the same name as a column (Value, Unit, Type) is hidden
  by that column; rename the variable.
- "Missing expression: If the keyword 'set' is intended to be part of an
  expression it needs to be bracketted": the name is a KQL keyword (set,
  range, type, on, by, ...); rename that alias or variable (DaySet, Days).
- "does not use the authenticated TargetUserId scope": pass the
  authenticated user as a plain string literal ('<user>') or through
  let TargetUserId = '<user>'; as the first argument of every Sensor call.
- "max(): function expects 1 argument": the larger of two values is
  max_of(a, b) (min_of for the smaller); max()/min() are aggregates.
- join errors: create the key column on both inputs first, then
  | join kind=inner (Other | project Day) on Day. A query-local name is not a
  column prefix (use the column name itself after the join).
- "Syntax error ... Expected: ;": each let statement must end with ';' and the
  final statement is the query result.
- A Sensor function or column name that does not exist: use the six documented
  functions and their listed columns only. SensorWorkoutSessions has no Unit
  column; DurationMin is in minutes, Distance in DistanceUnit (METER).
- Guard rejections: call only the documented Sensor functions, with the
  authenticated user as the first argument and the trusted datetime bounds as
  the second and third; no management commands, no external data, no other
  tables. A literal datatable or print is not a data source.
